## 表 4  预算扫描：关思考时把 max_tokens 加大能救回多少截断

| max_tokens | 截断题数 | 截断率 | 说明 |
|--:|--:|--:|---|
| 500 | 85/200 | 42.5% |  |
| 1024 | 78/200 | 39.0% | 比上一档少 7 题 |
| 2048 | 76/200 | 38.0% | 比上一档少 2 题 |
| 4096 | 76/200 | 38.0% | **无改善** |
| 8192 | 74/200 | 37.0% | 比上一档少 2 题 |

token 分布呈**强双峰**：`<500` 的 115 题（58%）、`=8192` 的 74 题（37%）、中间(500~8191)只有 11 题。

> 结论：截断**不是预算不足**，而是约 37% 的题模型**根本不吐 EOS**（一条道走到黑）。把预算从 500 提到 8192，截断只从 45.0% 降到 37.0%，且 8192 之后已饱和；代价是耗时 14m → 117m，总分反而 44.2 → 43.4。

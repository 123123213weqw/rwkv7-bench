🧠 端侧模型能力基准测试v3（xLeaves Benchmark v3）

📐 测试方法说明（点击折叠）
题库：iq_bank_v3，共 200 题，七个类别——Agent 能力 / 编码 / 数学 / 对话 / 脑筋急转弯 / 长上下文 / 其他，权重 20/20/20/10/10/10/10；难度 1-10 阶梯（easy 100 题 / medium 50 题 / hard 50 题）。题面自带日期锚点（避免模型不知日期），长上下文题由固定种子确定性生成、字节级可回归。
执行：每个模型独立起推理服务（llama-server，开启 --jinja 工具协议），由统一评测 harness 逐题请求。Agent 题走真实 OpenAI tools 协议多轮调用（工具返回为预设罐头结果，验证调用链与参数构造）；编码题提取代码后实际执行隐藏测试用例判分；数学题核对"最终答案"行；其余按关键词组命中判分。
采集：每题得分、耗时、token 用量与模型原始输出随做随落盘（results_v3_*.json），网页报告由守望进程每分钟自动重建——每测完一个模型，本页 1 分钟内即更新。
比分修正：全部模型测完后，由可靠大模型作为阅卷人，在同一上下文状态下逐题复核所有非满分回答的原始输出，识别"回答正确或更优、但被机械判分冤枉"的情形并按回答质量修正，raw 与 corrected 双分透明、修正理由留档，以此增加可信度（参照组自评仅做保守机械纠错并单独标注）。
📋 测试参数说明（点击折叠）
采样：temperature 0.2（对话类 0.7）· top_p 0.95 · repeat_penalty 未启用（默认 1.0）· max_tokens 8192。
上下文：KV 缓存统一 Q8_0 量化 · 上下文窗口 49152。
量化档：仅测试 Q4_K_M（下文简称 Q4，有损档）与 Q8_0（下文简称 Q8，无损档）两个档位。不测 F16——端侧显存与带宽资源紧张，F16 的体积和速度代价不现实；不测 Q6_K（Q6）——部分推理硬件（如 Vulkan 后端）对 Q6_K 内核支持不全、存在性能断崖，且其质量档位与 Q8 同处高原区，可参考 Q8 成绩。
理由：单一变量原则——所有模型同题库、同采样、同 token 预算，使分数差异只反映模型能力。温度取全池官方推荐交集的低区间，高温会引入采样噪声、让排名在重跑间漂移；8192 为思考型与普通模型的折中（4096 会截断思考链）。
已知偏差声明：① RWKV-World 官方 demo 的解码方式与本协议不同（temp 1 · top_p 0.5 · presence 1 · count 0.1 · decay 0.99，并关闭思维链）；本协议统一低温下 RWKV 存在重复循环风险，故表中 RWKV 行应视为下界。经补充实测 RWKV7-G1j-2.9B Q4 在官方解码下为 44.2 分（500/关思考）、48.3 分（8192/开思考），均高于本协议下的 41.2，下界判断成立；解码口径差异见表中 · 官方demo/demo采样 各行
② RWKV7-G1j-2.9B 的 Q4_K_M 档属量化受损，不适用本报告「≥5bpw 质量高原区」的档位假设：同模型换 Q8_0、同官方解码口径复测，总分 44.2 → 64.1（+19.9），撞 500 token 上限的题数 90/200 → 39/200，coding 41.2% → 80.0%、math 30.0% → 57.5%。Q4 档下 82% 的题无法输出终止符而跑满预算，属量化破坏了终止行为，非模型能力差异；该模型应以表中 · Q8 · 官方demo 一行为准；② 个别思考型微调变体在 8192 预算内思考链可能无法终止，属协议约束下的真实行为；③ 量化档随模型略有差异（表中已标注），均为 ≥5bpw 质量高原区档位；④ 比分修正已对称执行完毕（规则 A/B/C：基础设施故障题剔除分母、虚构陷阱题非编造响应记满分、药店题专业分诊行为记满分；每模型修正 0-2 处、理由留档 corrections_v3.json），修正后总分（★ 列）为最终成绩。
❓ 疑义问答说明（点击展开）

Q：为什么有些模型 Q4 量化的成绩反而比 Q8 更好？
A：大模型测试存在随机性。整个跑测历时约三天，无法进行多轮测试取均值（均值至少需要 10 次才有统计学说服力），因此只采用单次成绩——这不代表 Q4 优于 Q8。我也不会针对 Q8 反复重测直到它超过 Q4：一旦存在这种操作空间，就意味着我可以"让特定模型必须高于其他模型"，这是基准测试绝对不能允许的。一次成绩定格成什么样就是什么样，公平才有意义。

Q：为什么云端大模型的跑分甚至不如某些端侧模型？
A：大模型的"大"其实要打个问号——很多大模型的激活参数并不占绝对优势。更重要的是，本评测题目整体偏简单，仅针对端侧模型能力范围构建，没有施加很大压力（所以大家分数普遍偏高）。这份评测的目标不只是找出最好的端侧模型，而是找出最具性价比的端侧模型——题目并不针对旗舰模型的能力覆盖出题，大模型的深度能力得不到完整发挥，分数不高、甚至不如某些端侧模型是合理的（况且某些大模型确实也测出了问题）。

Q：我想申请模型重测可以吗？
A：不可以。这个基准测试虽然是个野鸡榜，但测试是一次性的：测完不重测，后续也不更新榜单。作为 AI 工作者，拿验证集做训练数据的情况见得不少了——重测意味着不公平，意味着模型可以通过针对性训练刷分。本评测发布后成绩冻结，永不更新。

Q：这份基准测试未来还会更新吗？
A：不会。更新意味着所有题目全部推翻、重新设计生成，工作量巨大，而我不愿意降低标准用同一套题反复测。而且评测有时并不能说明问题——93 分真的比 95 分差吗？噪声区间内的分差没有实际意义，只有数量级差距才有意义。大家可以用这份评测粗浅评估新模型的能力，但需要独立思考，不可全信。客观的基准测试需要大量精力来避免分数失真，我只会每隔一段时间做一次，不会持续维护；我鼓励大家参与基准测试这项工作，这样在挑选模型时才有更多数据支持部署决策。

Q：这份基准测试存在哪些问题？
A：野鸡榜单，问题不少：仅针对中文测试；简单题目占比更高（对 4-9B 级模型更友好）。但总的来说这是由它的定位决定的。我鼓励大家基于自己的实际场景做更多客观测试。这份榜单想得出的核心结论是：在硬件资源有限的条件下，选择哪个模型能更充分地发挥硬件的效率和能力。

Q：有推荐的模型吗？
A：我不想打广告（也没人给钱），但我会推荐两个：Ling-3.0-tiny（极低的上下文显存开销和激活参数，合理的智力水平）和 Ornith-1.5-35B-A3B（较小的运算压力和较高的智力水平）——它们在资源受限条件下工作良好，在自身能力分段内表现卓越，智力与知识储备都相当不错，也许未来端侧小型 MoE 就是版本答案。如果硬件足够好，Qwen3.8-27B 能获得堪比云端大模型的体验，但 dense 模型推理速度较慢。

📊 统计学趣味分析（点击折叠）

1. 勤勉-速度轴（diligence vs. velocity）：模型存在明显的两种风格，可通过总榜"耗时"列分辨。勤勉型模型（如 MiniCPM5-2B、Qwen3.5 家族）会更多搜集证据、有实锤后才下结论——长文计数题愿意逐条数完，但推理更慢；速度型模型更注重整体效率，在要求"用笨方法解决"的题目上倾向直接猜测答案（云端模型同样如此，GLM 参照组的长上下文失分即为此类）。

2. Ornith 的后训练是"速度型强化"：Ornith 系后训模型在更难的题目上表现更好、简单题略逊于原版底座，且推理速度大幅提升（35B 版 MTP 投机解码加持）。综合看，相对原版整体是加强的——代价是对话与通识类小幅回撤，收益是硬推理与速度。

3. MiniCPM5 的社区微调变体几乎全线扑街：三个变体两个崩、一个平庸，还贡献了全场唯一"未完赛"案例（1B-anti-hallucination 仅 40 题确证即弃）。建议选择社区模型时不要被介绍页洗脑，先小规模评测再决定是否采用。

4. 去审查（de-censoring）的能力代价真实但轻微：同源对照显示，去审查版在复杂问题上有损失，但幅度不大（Heretic 与原版总分差在噪声带内）。是否采用去审查版本，应结合自身需求决定，不必担心智力大幅受损。
